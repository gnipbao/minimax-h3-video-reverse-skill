# 视频观察与证据边界

## 能力检查产生的是状态，不是装饰性声明

| 实际情况 | 状态 | 可以交付 |
| --- | --- | --- |
| 完整视频不可访问；只看到封面/截图 | BLOCKED | 缺口、局部静态草稿；不能输出完整动作时间线 |
| 视觉覆盖完整，音轨内容未核实 | PARTIAL | 完整视觉方案；声音字段 N/A；若音轨存在且目标保真，另给原声继承交接 |
| 用户仅要视觉且视觉完整 | COMPLETE | 标明 scope=visual、audio_status=not_requested |
| 所需画面、时间、音频均核实 | COMPLETE | 相应范围内的完整反推 |
| 片段受损、尾部打不开 | PARTIAL | 只交付覆盖范围，列出缺段；不称全片已完成 |

若完整反推的关键视觉能力缺失，用 BLOCKED。PARTIAL 不能作为绕过关键视觉门槛的标签。

声音状态至少区分：`verified`（已实际核实内容）、`no_track`（文件无音轨）、`unavailable`（未能核实内容）、`not_requested`（用户选择排除）。这与 `audio_track_present`、原声复用目标分别记录；`unavailable` 不妨碍复用同一音频流，`no_track` 不等于已听到安静环境。具体分流见 [声音继承](audio-inheritance.md)。

## 五遍读取

1. **全局**：识别有效视觉范围、文件画幅与内容画幅、主体、媒介、声音访问情况、开场与结尾。
2. **边界**：复看真实切镜和时空重置，独立登记淡入淡出、叠化、黑场及字卡。
3. **连续覆盖**：从起点到结束，每一段都有归属；停顿和余波有真实时长，不跳过。
4. **局部加密**：在碰撞、动作反向、手指接触、变形、遮挡、文字闪现附近补看连续帧。
5. **倒查**：复查第一帧、首个有效状态、最后三分之一、最后动作和最终可解码帧。

抽帧/转录工具产出只是待检查材料。不能把“已提取 300 帧”写成“已检查 300 帧”，也不能把自动转录当作逐字已核实。

本地 `scripts/sample_frames.py` 按实际解码 PTS 选择最接近请求时刻的帧，并自动带上第一帧与最后一帧。其 manifest 中 `visual_content_reviewed=false`；看过哪些帧要另记。帧的实际时间可能不同于请求时间，必须使用返回值。最后一帧持续时间缺失时，visual_end_s 保留 null，不拿平均帧率补数。

## 疑点驱动的视觉返图

借鉴 Hypit 的参考细读方法：先理解整体，再用能回答当前问题的图像尺度细看，发现新关系后更新整体理解。这里的返图是将真实源帧或片段送回宿主的视觉查看能力；抽取命令、文件名或清单文字不提供像素观察。它不依赖 Hypit Runtime 或另一套视觉模型。

| 当前疑点 | 下一次应看的证据 | 完成条件 |
| --- | --- | --- |
| 片段在哪里、全片怎样发展 | 带实际源时间的全局联系表，长片分页 | 每段可定位；短事件仍需密集复看 |
| 正背面、部件、文字、材质认不清 | 对应原尺寸帧；必要时带全图位置的原像素局部裁切 | 区分候选解释所需细节清楚可见 |
| 谁在动、接触先后、遮挡或形变怎么发生 | 疑点前后的相邻帧/密集序列；有播放能力时看局部片段 | 有初态、中间变化、截止及必要的进出场关系 |
| 是切镜、转身、复位还是同一持续对象 | 同时含前一状态和后一状态的交接区间 | 画面重置与镜内动作分清；持续图层另记生命周期 |
| 用户纠正与旧文字冲突 | 重新打开争议时段和原尺寸帧 | 修正事实及所有受影响输出；证据不足仍 uncertain |

一个问题用最少的充分证据解决。先记问题和候选读法，再选范围与尺度；不预填答案。联系表只用于导航和变化对照；小格仍不清时停止凭缩略图推断，打开所选原图。空间细节不足增加分辨率，时间关系不足增加邻接时刻，两者不能互相替代。需要上下文时扩展片段，不只盯一个孤立裁切。

**实际查看门槛**：生成后用宿主图片查看工具打开 PNG，并按需要打开原尺寸帧；有 `view_image` 时可用其原尺寸模式。只有工具文本、图片未成功返回或视觉能力不可用，记录“待查看”，不填写 reviewed。裁切、标签和联系表只是查看衍生物，保留原图和实际时间；不得用重绘、补帧或增强猜字填补源证据。单帧不能确认动作；没有播放能力时明确依据连续帧范围。

记录简洁的观察回执：`问题 / 选取范围与尺度 / 实际查看的证据 / 可见发现 / 解释或未决项 / 受影响事实`。与现有事实表放在一起即可，不强制新增五份文档。对照初态与结果时继续按本参考的视角、表面和形变规则登记。停止条件是证据足以回答问题并已回写；仍有关键歧义时保持缺口，按需要询问用户解释，不以“又抽了更多帧”结案。

### 把已抽取帧做成可查看联系表

工具复用 `sample_frames.py` 的清单；从实际源帧等比缩略排版，标签在图外，索引链接原尺寸图片。需要当前 Python 已有 Pillow；可选用宿主现成的图像运行环境，缺依赖时清楚报告，不自动安装，也不要求安装 Hypit。示例时刻只说明命令，实际按疑点选取：

先核对现有解释器是否可导入 Pillow；若默认 Python 缺少而宿主提供工作区依赖定位工具，使用它返回的已有解释器路径执行下面命令。没有可用排版环境时仍可通过宿主直接打开原帧执行观察，不把联系表依赖缺失当成完整视觉能力缺失。

```bash
python3 scripts/sample_frames.py /path/to/reference.mp4 --output /tmp/h3-focus-frames --at 1.2 1.4 1.6 1.8
python3 scripts/build_review_sheet.py /tmp/h3-focus-frames/manifest.json --output /tmp/h3-focus-review --question "Which surface is visible, and what changes?" --range 1.2 1.8 --columns 3 --rows 2 --cell-width 480
```

两个输出目录均须为新目录。`--range` 使用清单 `range_s` 的归零源时间；标签同时保留原始 PTS，不能把请求时间或平均 fps 当实际时间。全局首尾帧由抽帧工具自动带入，局部返图时按范围筛掉不属于疑点的远端帧；检查交接则主动包含相邻镜头。工具核验所选帧哈希，输出 PNG、`review.json` 与 `review.md`，保持未复核状态。接下来必须打开 PNG/原图；脚本不决定哪些帧足够，也不推断动作。

用户指出视觉遗漏时，选一张小型初态—关键变化—截止态证据图展示纠正。图中保持源视频像素含义，实际源时间标清；不要把联系表作为模型首帧参考，I2V 仍绑定选定时刻的原始单帧。用户只要纯文字时，图像用于内部检查，不增加交付负担。

## 高保真动作核对

遇到多次接触或快速反向，按“准备—接近—接触—分离—再次动作—反应”寻找局部证据。实际没有的阶段不补。为每次接触记录主体、动作部位、目标、接触点、离开方向和作用后的状态；能辨认时写左右/近远位置，不凭模糊轮廓猜测。

同一段至少分开三条变化轨：主体动作、镜头运动、环境/图形。这样可以发现“人物向前走”被误写为推镜，或“遮挡/模糊”被误写为切镜。静态参考图只包含选定瞬间，不把几个动作叠成多只手/多个道具。

末段倒查时先问：最后清楚可见的状态是什么，后面是否还有黑场、字幕、转场，动作是否仍在继续。记录最后可解码帧与视觉结束依据，不能把历史文案中的动作结束时刻直接当作文件终点。

实体稳定项按实际范围声明。保留身份和部件对应关系，不用“形状完全不变”锁死已观察到的膨胀、展开、拉伸或风格切换。看不到的因果只写可见变化，保留未知原因。

## 视角、表面与视觉结果

每个真实 Shot 先识别摄影机看的是主体哪一面：正面、背面、侧面、俯视或无法确认；写朝向镜头的可见部位与结构。景别“下半身特写”“产品细节”不能代替观察方向。分清画面左/右与主体自身左/右，不因另一镜有正面标识就把背面解释为正面。角度不清时回看邻接帧和轮廓；仍不清则 uncertain，不凭产品常识补背面设计。

对展开、卷收、覆盖、揭露、镂空和形变，把动作与视觉结果分别记入现有事实：

| 要核对什么 | 最小记录 |
| --- | --- |
| 初态 | 当前表面、轮廓、卷折/堆叠、哪些区域露出或被覆盖、开口的形状与位置 |
| 操作 | 谁抓哪个部位，朝画面哪个方向施力，接触是否持续 |
| 中间变化 | 材料沿何路径移动，覆盖边界怎样移动，开口/体积/层次怎样改变 |
| 截止状态 | 哪些区域最后露出或被覆盖、最终形状、附件位置、是否仍握持/受力 |
| 变化归属 | 是外层材料、内层结构、主体形状还是摄影机发生变化 |

例如原创教学场景：箱包背面折起的布片向下展开，原先露出的条纹标签被覆盖，狭短的开口变成竖长开口。不能压缩为“整理箱包，展示弹性”；也不能让硬壳本体随布片一起变软。主体身份和材料可以稳定，局部覆盖关系必须允许实际变化。

关键效果至少复看初态、中间态与最后可见状态。多张端点帧仍不能证明看不到的释放、转身或自动复位；硬切后恢复外观属于新镜头状态。先记可见几何变化，再解释“显瘦、弹性、可折叠”等演示意图。

完成观察后，为会改变复刻结果的视角、结构、覆盖/形变和终态建立少量必保锚点，按 [事实契约](evidence-contract.md) 对照到具体事实和提示词。锚点应由当前媒体决定，不能把教学案例的背面或展开强加给所有视频。

## 时间的三个概念

- `container_duration`：容器总体时长，可能包含比画面更长的音轨。
- `visual_duration`：有效视频流的显示范围。
- `last_frame_time`：最后一帧开始显示的时间，不一定等于视觉结束时间。

可变帧率使用 PTS，不能拿平均 fps 推算每帧时间。最后一帧没有可用持续时间时，标记终点依据和不确定性。旋转元数据、非方形像素和内部黑边会影响画幅判断，宽高数字不能替代看图。

观察只能精确到 0.1 秒，就保留该精度。H3 要求的 `00:05.700` 是把约 5.7 秒写入固定格式，不能宣传为毫秒级观察。参考图要落在有效 Shot 范围内；若选首个清晰帧晚于开头，必须记录被跳过开场如何保留/装配，不能悄悄删掉动作。

## 真切镜与连续变化

可作为切镜证据：背景、空间关系、视角与时间的离散重置；明确硬切、叠化或时间跳跃。反向核对前后帧，必要时标疑似隐藏切镜。

不可单独作为切镜证据：摄影机拉远、人物靠近、UI 出现、遮挡掠过、瞬时运动模糊、灯光变化、持续形变。例：近景连续拉到第三人称游戏视角，仍可能是一个 Shot。

## 状态比物体清单更有用

为重复实体记录最小状态链：

```text
实体：红色杯子
身份锚点：杯身红色、白色把手
状态：桌面 → 手持 → 靠近嘴边 → 被脸与手遮住 → 再次可见
终态：仍被握住
允许变化：旋转、遮挡、出画
禁止凭空断言：丢弃、破碎、换杯
```

接触前、接触中、分离后要分清。看不到出画后的结果就记录未知，不猜测。超现实形态先描述几何变化，再给有证据的语义；不要把猫脸鱼体自动改回普通猫或普通鱼。

## 图层与声源

平台角标、播放器进度条通常是素材载体。教程中的按钮、鼠标与软件窗口则可能是目标内容。按视频用途判断，不按“UI”这个名字整类删除。

视觉不自动证明声音：打击、雨滴、烟雾、嘴部运动都不能成为虚构音效或对白的理由。只在实际听清时区分同步事件、环境底声、画内音乐和观众侧配乐。用户新增的声音记为创作要求。若目标沿用原声，保留源音轨的连续时间线，不能因分镜或分段而重复开头；核对结果时把音频信号复用与口型同步分开验收。

音频只核实一部分时，不允许把未覆盖部分推成静音；交付时列出核实范围。对白原语言保留；听不清用 `[unclear]`，实际结束截断用 `<cutoff>`。
